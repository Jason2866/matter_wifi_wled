# AGENTS.md — Matter WiFi WLED Bridge

Guidelines for AI coding agents working in this repository.

## Project Overview

ESP32 firmware (PlatformIO, dual Arduino + ESP-IDF framework) that bridges WLED LED
controllers to the Matter smart home protocol. Runs on a separate ESP32 that discovers
WLED devices via mDNS and controls them over HTTP JSON API, exposing each as a Matter
Extended Color Light endpoint.

The codebase is compact: 6 `.cpp` files + 5 `.h` headers in `src/` and `include/`.

## Build Commands

```bash
# Build default target (ESP32-S3, 8MB flash)
pio run -e esp32s3

# Build classic ESP32 (experimental)
pio run -e esp32

# Build ESP32-S3 with 16MB flash
pio run -e esp32s3_16mb

# Upload via USB serial
pio run -e esp32s3 -t upload

# Upload via OTA
pio run -e esp32s3 -t upload --upload-port matterwled.local

# Monitor serial output
pio device monitor -b 115200

# Clean build artifacts
pio run -e esp32s3 -t clean

# Full clean (removes all downloaded components)
pio run -e esp32s3 -t fullclean
```

**First build takes 10-30 minutes** (compiles Matter SDK from source). Subsequent
incremental builds are much faster.

## Tests

Integration tests run against a **live device** over the network using pytest. They
exercise the REST API, web UI, WLED discovery, config persistence, and bridge-to-WLED
forwarding. There are no unit tests — the firmware has no test harness on-device.

### Prerequisites

```bash
pip install pytest requests
```

The device must be flashed and reachable on the network.

### Running Tests

```bash
# Run standard tests (requires BRIDGE_IP env var or defaults to 192.168.178.212)
BRIDGE_IP=<device-ip> pytest tests/

# Run including destructive tests (factory reset, config wipe, etc.)
BRIDGE_IP=<device-ip> pytest tests/ --run-destructive

# Verbose output
BRIDGE_IP=<device-ip> pytest tests/ -v
```

### Test Structure

```
tests/
  conftest.py           # Fixtures (bridge_url, etc.), markers, --run-destructive flag
  test_integration.py   # 46 tests across 9 test classes
pytest.ini              # Marker registration and default options
```

### Test Categories

| Class | Tests | What it covers |
|-------|-------|---------------|
| `TestBridgeStatus` | 11 | `/api/status` fields, WiFi info, Matter state, pairing |
| `TestBridgeConfig` | 9 | `/api/config` structure, light slot format, MAC field |
| `TestLightStates` | 7 | Per-light on/off, brightness, color, endpoint IDs |
| `TestWledDiscovery` | 6 | `/api/wled/discover` returns valid WLED devices |
| `TestWledDevices` | 4 | Discovered devices have IP, name, LED count |
| `TestWebUI` | 3 | HTML pages load, contain expected elements |
| `TestConfigModification` | 4 | Save/update/delete light config via REST API |
| `TestBridgeToWledForwarding` | 1 | Light state changes forwarded to WLED device |
| `TestMatterProtocol` | 1 | Placeholder for future Matter-level tests (skipped) |

Destructive tests (marked `@pytest.mark.destructive`) are skipped by default because
they modify device state (factory reset, clear all config). Use `--run-destructive`
to include them.

## Project Structure

```
src/
  main.cpp              # Entry point: setup(), loop(), ArduinoOTA
  matter_manager.cpp    # Matter stack: node, endpoints, attribute callbacks
  web_ui.cpp            # Web server, REST API, captive portal, WiFi management
  wled_output.cpp       # HTTP POST to WLED JSON API
  wled_discovery.cpp    # mDNS discovery of WLED devices
  config_store.cpp      # NVS persistence for light configuration
include/
  matter_manager.h      # Public API: matterSetup(), matterLoop(), etc.
  web_ui.h              # Public API: webSetup(), webLoop(), etc.
  wled_output.h         # WledOutput class
  wled_discovery.h      # wledDiscoveryInit(), wledDiscover()
  config_store.h        # ConfigStore class, LightConfig/LightState structs
platformio.ini          # Build configuration (3 environments)
idf_component.yml       # ESP-IDF Component Manager manifest (esp_matter)
```

## Build System Notes

- **Dual framework**: Arduino (web server, OTA, WiFi) + ESP-IDF (Matter SDK, mDNS, NVS)
- Three Python pre/post scripts handle PlatformIO quirks for this dual-framework setup
- `lib_ignore = Matter` prevents conflict with Arduino's built-in Matter library
- `idf_component.yml` in root is the canonical manifest; `src/idf_component.yml` is
  auto-generated by `setup_matter_component.py` — do not edit it directly
- `sdkconfig.esp32*` files are generated — do not edit manually

## Code Style

### Formatting
- **2-space indentation**, no tabs
- **K&R brace style**: opening brace on same line
- No strict line length limit; aim for ~100 characters
- Space after keywords (`if (`, `for (`), no space before function parens (`foo()`)

### Naming Conventions
- **Files**: `snake_case.cpp` / `snake_case.h`
- **Classes/Structs**: `PascalCase` (`ConfigStore`, `WledOutput`, `LightConfig`)
- **Functions**: `camelCase`, free functions prefixed by module (`matterSetup()`, `webLoop()`, `wledDiscover()`)
- **Variables**: `camelCase`; `m` prefix for module-static state (`mNode`, `mStarted`); `s` prefix for file statics (`sMdnsReady`)
- **Constants**: `UPPER_SNAKE_CASE` (`MAX_LIGHTS`, `HTTP_TIMEOUT_MS`)
- **Macros**: `UPPER_SNAKE_CASE`
- **Enum values**: `UPPER_SNAKE_CASE` with type prefix (`LIGHT_TYPE_RGB`)
- **ESP-IDF log tags**: short string literals (`"Matter"`, `"WLED"`, `"Web"`, `"Config"`)

### Header Guards
- Always use `#pragma once` (no `#ifndef` guards)

### Include Order
1. Own header (in `.cpp` files)
2. Project headers (`"quotes"`)
3. Arduino/framework headers (`<angle brackets>`)
4. ESP-IDF headers (`<angle brackets>`)
5. Third-party libraries (`<angle brackets>`)
6. C++ standard library (`<angle brackets>`)

Project-local headers use `"quotes"`, everything else uses `<angle brackets>`.

### Types
- **Fixed-width integers** strongly preferred: `uint8_t`, `uint16_t`, `uint32_t`
- **Arduino `String`** for web/WiFi operations; **`char[]`/`const char*`** for structs and buffers
- **`std::string` is never used** — do not introduce it
- `bool` for flags (not Arduino `boolean`)
- `float` for color math

### Error Handling
- **No exceptions**: never use `try`/`catch`/`throw`
- ESP-IDF calls: check `esp_err_t`, log with `ESP_LOGE`/`ESP_LOGW`, return early
- Functions return `bool` (success/failure) or `int` (-1 for not-found)
- NULL checks with `if (!ptr)` pattern

### Logging
- Use **ESP-IDF logging exclusively**: `ESP_LOGI`, `ESP_LOGW`, `ESP_LOGE`, `ESP_LOGD`
- **Never use `Serial.println()`** for logging (Serial is only initialized, not used for output)
- Tags are short module names: `"Main"`, `"Matter"`, `"WLED"`, `"Web"`, `"Config"`, `"Discovery"`

### Memory Management
- **Stack allocation** for buffers (`char buf[128]`)
- **Static globals** for module state (arrays sized to `MAX_LIGHTS`)
- **No heap allocation**: no `malloc`/`free`, no `new`/`delete`, no smart pointers
- Use `memset(&obj, 0, sizeof(obj))` or `= {}` for zero-initialization
- `volatile` for variables shared between Arduino loop and Matter task context

### Const Correctness
- Use `const` references for input parameters: `const LightConfig& cfg`
- Mark accessor methods `const`: `uint8_t getLightCount() const`
- Non-const accessor uses `Mut` suffix: `getLightMut()` vs `getLight()`

### Comments
- File headers: `/* */` block comment describing the file's purpose
- Section dividers: `// ── Section Name ──────────────────` (Unicode box-drawing dashes)
- Inline: `//` comments; limited `/** */` Doxygen for public API in headers
- Numbered steps for initialization sequences: `// 1. Load config`, `// 2. Start Matter`

### Arduino Patterns
- Standard `setup()` / `loop()` entry points in `main.cpp`
- `millis()` for non-blocking timing; avoid `delay()` except during init
- `Preferences` API for application-level NVS storage
- `PROGMEM` + `server.send_P()` for large static HTML

### ESP-IDF Patterns
- Direct NVS API (`nvs_open`/`nvs_close`) for Matter/CHIP namespaces
- `esp_http_client` for outbound HTTP to WLED devices
- `mdns_*` API for service discovery
- `esp_matter::*` namespaced API for Matter SDK integration
